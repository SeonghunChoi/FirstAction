# 새 공격 추가 절차 (C++ 변경 0줄)

Step 8-2에서 플레이어의 약-강 분기를 새 기술로 바꾸면서 실제로 거친 순서다. 핵심 메시지 "공격 하나는 데이터 한 장"을 확인하는 기록이다.
적의 새 공격(8-1 엘리트 돌진 베기)도 같은 순서이고, 마지막에 패턴 데이터에 패턴 한 줄을 더하는 것만 다르다.

## 데이터만으로 되는 범위

| 하고 싶은 것 | 데이터만으로 | 이유 |
|---|---|---|
| 기존 입력(약·강)으로 콤보에 가지 붙이기·바꾸기 | 된다 | 분기는 `UAttackDataAsset::ComboLinks`에만 있다 (설계 규칙 4) |
| 공격 성질(피해, 충격, 간격, 히트스톱, 워핑 거리, 패리 반응 본) | 된다 | 모두 공격 데이터 칸 |
| 타이밍(판정, 콤보·캔슬 구간, 워핑 구간, 멈출 간격) | 된다 | 모두 몽타주 노티파이 (설계 규칙 3) |
| 적이 새 공격을 쓰게 하기 | 된다 | 패턴 데이터의 시작 공격 + 입력 태그 순서 |
| 새 버튼(새 입력 태그) | 안 된다 | 태그는 C++ 네이티브 태그로만 정의한다 (설계 규칙 10) |
| 칼 이외의 판정(주먹, 발) | 안 된다 | 판정은 무기 메시 소켓 쌍 스윕 하나 (`UMeleeTraceComponent`) |
| 차지, 홀드처럼 입력 방식이 다른 공격 | 안 된다 | `GA_MeleeAttack`은 누름 → 몽타주 재생만 안다 |

## 순서

### 1. 애니메이션 리타깃
- 원본이 UE5 마네킹이 아니면 같은 팩의 리타기터로 리타깃한다 (`RTG_UAL1_Manny`, `RTG_UAL2_Manny`).
- 저장 위치 `Portfolio/Animations/Retargeted/<팩>/`, 이름 `A_<팩>_<원본 이름>`.
- 시퀀스의 **Enable Root Motion**을 켠다. 모션 워핑(6-2)이 루트 모션을 전제한다.

### 2. 몽타주
`Portfolio/Animations/Montages/AM_<팩>_<이름>`, DefaultSlot. 기존 공격 몽타주를 옆에 열어 두고 따라 배치한다.

| 노티파이 | 위치 | 없으면 |
|---|---|---|
| Motion Warping (Skew Warp, `AttackTarget`) | 휘두르기 전 앞으로 나가는 구간 | 대상에게 붙지 않는다 |
| `ANS_HitWindow` | 칼이 지나가는 구간. 휘두름마다 하나 | 맞지 않는다 |
| `ANS_TagWindow` `Window.Combo` | 휘두르기 끝 ~ 회복 앞쪽 | 다음 공격으로 이어지지 않는다. 끝 노드면 넣지 않는다 |
| `ANS_TagWindow` `Window.Cancel` | 휘두르기 뒤 ~ 끝 | 회피·점프·가드로 끊을 수 없다 |
| `ANS_AttackReach` (`StopGap`) | 워핑 구간 시작을 덮게 (선택) | 몸이 닿는 거리까지 붙는다. 너무 가까워 헛치면 넣는다 (6-8 후속) |

- 클립이 짧아 블렌드 아웃이 콤보 구간을 먹으면 회복 클립을 이어 붙인다 (4-3, `_Rec`).

### 3. 공격 데이터
`Portfolio/Data/Attacks/DA_Attack_<이름>`. 성격이 비슷한 기존 공격을 복제해 시작한다.

| 칸 | 정하는 것 |
|---|---|
| `Montage` | 2의 몽타주 |
| `Damage` | 체력 피해 |
| `Impact Force` | 상대 충격량 = 충격 ÷ 맞는 쪽 질량. 반응 단계(움찔 < 250 ≤ 경직 < 700 ≤ 넘어짐)와 경직치 피해(0.07 ×)가 여기서 나온다 |
| `Post Hit Spacing` | 맞힌 뒤 두 몸 사이 간격. 작으면 붙은 채 이어 가고, 크면 벌어진다 |
| `Post Hit Move Duration`, `Hit Stop Duration` | 밀려나는 시간, 멈춤 시간 |
| `Max Warp Distance` | 대상을 찾고 붙는 최대 거리 |
| `Attack Bone` | 패리당했을 때 흔들릴 공격자 본 |
| `Combo Links` | 이 공격 뒤에 이어질 공격. 끝 노드면 비운다 |

### 4. 콤보에 연결
- 이 공격으로 들어오는 앞 공격 데이터의 `Combo Links`에 `{입력 태그, 새 공격}`을 넣거나 바꾼다.
- **공격 데이터는 플레이어와 적이 같이 쓴다.** 링크를 바꾸면 그 경로를 타는 적 패턴도 바뀐다. 적 패턴 데이터의 입력 태그 순서를 확인한다.
- 링크로 순환(A → B → A)을 만들 수 있다. 맞을 때마다 경직이 나는 공격이면 적이 반격 없이 갇히므로 피한다.

### 5. 확인
| 로그 | 뜻 |
|---|---|
| `콤보: <앞 공격> --<입력 태그>--> <새 공격>` | 링크 연결 |
| `워핑: <새 공격> → <대상> (간격, 멈출 간격, 이동 / 최대)` | 워핑 구간과 거리 |
| `판정 구간 끝: 스윕 N프레임, 맞힘 M` | 판정 구간 |
| `[해석] … 상대 충격량 X(단계) … 경직치 Y` | 반응 단계와 경직치 피해 |

`showdebug abilitysystem`으로 구간 태그(`Window.Combo`, `Window.Cancel`)가 몽타주대로 붙는지 본다.

## 8-2 예시: 약-강 = 경직치를 깎는 기술

| 결정 | 내용 |
|---|---|
| 붙인 위치 | 약1의 강 분기를 `Heavy_01` → 새 공격으로 교체. 약-강과 약-약-강이 다른 기술이 됨 |
| 클립 | Quaternius UAL1 `Sword_Attack` (CC0) → `A_UAL1_Sword_Attack`, `AM_UAL1_Sword_Attack` |
| 성격 | 강공격급 충격, 짧은 간격. 경직치를 많이 깎고 붙은 채로 다시 시작 |

`DA_Attack_LightHeavy`: Damage 12, Impact Force 48000, Post Hit Spacing 60, Post Hit Move Duration 0.15, Hit Stop 0.08, Max Warp 150, Attack Bone `hand_r`, Combo Links 없음.

| 상대 | 상대 충격량 | 반응 | 경직치 피해 |
|---|---|---|---|
| 일반 적·더미 (80kg) | 600 | 경직 | 42 (약1의 두 배) |
| 엘리트 (180kg) | 267 | 경직 | 18.7 |

바뀐 에셋: 새 3장(`A_`, `AM_`, `DA_`), 기존 1장(`DA_Attack_Light_01`의 링크 한 줄). 적 `LightHeavy` 패턴은 약1 → 약 → 강이라 약2의 링크를 타므로 바뀌지 않았다.

### 이 과정에서 드러난 것
- **경직이 눈에 보이지 않았다.** 움찔과 경직이 같은 몽타주(`AM_UAL1_Hit_Chest`, 약 0.15초)라 구분되지 않았다. 몽타주 `Rate Scale` 0.5인 경직 전용 몽타주(`_Stagger`)를 만들어 캐릭터 데이터의 경직 칸만 바꿨다 (약 0.5초). 역시 데이터만으로 해결했다.
- **엘리트 질량을 바꿨다 (200 → 180kg).** 경직이 보이게 되자, 약-강·강공격으로도 엘리트를 끊는 쪽을 골랐다. 몸의 데이터 한 칸으로 모든 공격의 반응이 함께 바뀐다 (`Docs/Tuning.md`).
- **크래시 하나는 C++로 고쳤다.** 같은 적에게 붙어 약-강을 거듭 넣다 엔진의 물리 애니메이션 틱이 빈 뼈 배열을 읽어 멈췄다. 새 공격과 무관한 부위 반응 컴포넌트의 문제라 별도 커밋으로 고쳤다.
